# Cloudflare, D1 и остальное: пошаговая инструкция

Эта инструкция для тех, кто делает это впервые. Если какое-то слово непонятно, смотри словарь в начале. Названия пунктов в панели Cloudflare иногда немного меняются, но логика остаётся той же.

## Как всё устроено

```
Браузер посетителя
   |
   |  открывает сайт (картинки, JS, CSS)           -> Cloudflare Pages (статические файлы)
   |  запрашивает /api/content, /api/track, ...    -> Pages Functions (папка functions/api)
   |                                                       |
   |                                                       v
   |                                               D1 (база данных SQLite)
```

Отдельного сервера нет. Файлы сайта раздаёт Cloudflare, а код из папки `functions/` запускается на серверах Cloudflare в момент запроса. Этому коду нужна база, и ей служит D1.

## Словарь

| Термин                    | Что это простыми словами                                                                                                           |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| Cloudflare                | Сервис, который хостит сайты, ускоряет их (CDN), управляет доменами и защищает от атак                                             |
| Pages                     | Хостинг для сайтов. Подключаешь репозиторий GitHub, и после каждого `git push` сайт собирается и обновляется сам                   |
| Pages Functions           | Серверный код в папке `functions/`. Запускается, когда кто-то обращается к адресу `/api/...`. Платить за отдельный сервер не нужно |
| Worker                    | Движок Cloudflare, на котором выполняются функции. Это не полноценный Node.js, но обычный JS и TS работают                         |
| D1                        | База данных SQLite, которую держит Cloudflare. Здесь лежат тексты сайта, история версий, аналитика, сессии                         |
| Binding (привязка)        | Способ выдать функции доступ к ресурсу. Привязка D1 с именем `DB` значит, что в коде база доступна как `env.DB`                    |
| Миграция                  | SQL-файл из папки `migrations/`, который создаёт или меняет таблицы. Применяется командой, и каждый файл применяется один раз      |
| Wrangler                  | Консольная утилита Cloudflare (`npx wrangler ...`). Через неё создают базу и применяют миграции                                    |
| Переменная                | Настройка окружения, которую видно в панели (например, `ADMIN_TG_ID`)                                                              |
| Секрет                    | Настройка, значение которой после сохранения скрыто (например, `SESSION_SECRET`)                                                   |
| Production и Preview      | Боевая версия (основная ветка) и пробные версии других веток. Переменные задаются отдельно для каждой                              |
| `.dev.vars`               | Файл с секретами для локального запуска. Он не должен попадать в Git                                                               |
| OIDC                      | Стандартный способ входа через внешний сервис. Здесь внешний сервис это Telegram                                                   |
| Client ID и Client Secret | Логин и пароль вашего приложения у Telegram. Выдаются в BotFather в разделе Web Login                                              |
| Redirect URI              | Адрес вашего сайта, куда Telegram возвращает пользователя после входа: `https://ваш-сайт/api/auth/callback`                        |
| Allowed URLs              | Список адресов, которые вы заранее разрешили в BotFather. Telegram работает только с ними                                          |
| Сессия и cookie           | После входа сайт выдаёт браузеру подписанную cookie. По ней админка узнаёт, что это вы                                             |
| Домен и DNS               | Адрес сайта. Бесплатный адрес от Cloudflare выглядит как `имя.pages.dev`                                                           |

## Шаг 0. Что должно быть установлено

1. Node.js версии 20 или новее. Проверка: `node -v`.
2. Git. Проверка: `git --version`.
3. Аккаунт GitHub и аккаунт Telegram.
4. Распакуй проект и выполни `npm install` в его папке.

## Шаг 1. Репозиторий на GitHub

```bash
git init
git add .
git commit -m "portfolio"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/ИМЯ_РЕПОЗИТОРИЯ.git
git push -u origin main
```

Файл `.dev.vars` уже перечислен в `.gitignore`. Перед пушем проверь командой `git status`, что его нет в списке. Если репозиторий публичный, в нём не должно быть токенов и секретов.

## Шаг 2. Аккаунт Cloudflare

Зарегистрируйся на dash.cloudflare.com и подтверди почту. Для бесплатного тарифа платёжная карта обычно не нужна. Домен покупать не требуется.

## Шаг 3. Войти в Wrangler

```bash
npx wrangler login
```

Откроется браузер. Разреши доступ. В терминале появится сообщение об успешном входе.

## Шаг 4. Создать базу D1

```bash
npx wrangler d1 create snak-db
```

В ответ Wrangler напечатает блок с `database_id` (длинная строка из букв и цифр). Скопируй её и вставь в файл `wrangler.toml` вместо `PASTE_DATABASE_ID_HERE`. Если Wrangler предложит сам дописать конфигурацию, можно согласиться, но проверь, что в итоге `binding = "DB"`.

## Шаг 5. Создать таблицы

```bash
npm run db:migrate
```

Команда выполнит файлы из `migrations/` на настоящей (удалённой) базе. Проверить результат можно так:

```bash
npx wrangler d1 execute snak-db --remote --command "SELECT name FROM sqlite_master WHERE type='table'"
```

В списке должны быть `content`, `agg`, `sessions`, `audit` и другие. Тот же список виден в панели: Storage and Databases, D1, `snak-db`.

## Шаг 6. Создать проект в Pages

1. Панель Cloudflare, раздел Workers and Pages, кнопка Create.
2. Вкладка Pages, затем Connect to Git. Разреши Cloudflare доступ к GitHub и выбери репозиторий.
3. Настройки сборки:
   - Framework preset: None
   - Build command: `npm run build`
   - Build output directory: `dist`
   - Root directory: оставь пустым
4. Нажми Save and Deploy. Через пару минут появится адрес вида `https://имя.pages.dev`.

Сайт уже откроется, но админка и счётчик пока не работают: базе ещё не выдан доступ.

## Шаг 7. Привязать D1 к проекту

Проект Pages, Settings, раздел Bindings (в некоторых версиях панели Functions, D1 database bindings). Add, тип D1 database:

- Variable name: `DB` (именно так, заглавными)
- D1 database: `snak-db`

Сделай это для окружения Production. Если планируешь пробовать другие ветки, повтори для Preview.

## Шаг 8. Переменные и секреты

Settings, Variables and Secrets, Add. Для Production:

| Имя                | Тип    | Значение                                      |
| ------------------ | ------ | --------------------------------------------- |
| `TG_CLIENT_ID`     | Text   | Client ID из BotFather (числовой ID бота)     |
| `TG_CLIENT_SECRET` | Secret | Client Secret из BotFather. Это не токен бота |
| `ADMIN_TG_ID`      | Text   | Твой числовой Telegram ID                     |
| `SESSION_SECRET`   | Secret | Длинная случайная строка, минимум 32 символа  |

Случайную строку можно получить командой `openssl rand -base64 48`.

Необязательные переменные:

| Имя            | Тип    | Зачем                                                                                                                                |
| -------------- | ------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| `SITE_URL`     | Text   | Адрес сайта без слэша в конце (например `https://имя.pages.dev`). Нужен при сборке для превью-карточки, `sitemap.xml` и `robots.txt` |
| `TG_BOT_TOKEN` | Secret | Токен бота для сообщений в Telegram о входе с нового устройства. Напиши боту и нажми Start, иначе он не сможет тебе писать           |

Часовой пояс статистики задаётся в `wrangler.toml` в строке `STATS_TZ`, например `"Europe/Amsterdam"`.

## Шаг 9. Настроить вход через Telegram

1. Открой @BotFather, команда `/mybots`, выбери бота.
2. Bot Settings, Web Login (если видишь старый экран с виджетом, переключись на OpenID Connect).
3. В Allowed URLs добавь оба адреса, точно в таком виде:
   - `https://имя.pages.dev`
   - `https://имя.pages.dev/api/auth/callback`
4. BotFather покажет Client ID и Client Secret. Их и нужно вписать в переменные из шага 8.

Токен бота (длинная строка с двоеточием) сайту не нужен. Никому его не показывай. Если он уже где-то засветился, отзови его: `/mybots`, бот, API Token, Revoke current token.

### Какие адреса (callback) куда вписывать

Вход устроен так: `/api/auth/login` отправляет браузер в Telegram, Telegram возвращает его на `/api/auth/callback` с одноразовым кодом, а сервер меняет код на подтверждение личности (с помощью Client Secret) и открывает сессию.

| Где                                | Что вписать                                                         | Зачем                                                                                                                                                                            |
| ---------------------------------- | ------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| BotFather, Web Login, Allowed URLs | `https://имя.pages.dev` и `https://имя.pages.dev/api/auth/callback` | Telegram работает только с адресами, добавленными заранее                                                                                                                        |
| BotFather, свой домен              | те же две строки, но с твоим доменом                                | Для каждого домена нужна своя пара. `www.` и домен без него считаются разными сайтами                                                                                            |
| BotFather, локальный запуск        | `http://localhost:8788` и `http://localhost:8788/api/auth/callback` | Telegram может не принять http, тогда проверяй вход на развёрнутом сайте                                                                                                         |
| Cloudflare Pages                   | ничего                                                              | Callback это обычный адрес сайта (файл `functions/api/auth/callback.ts`)                                                                                                         |
| Код проекта                        | ничего                                                              | `login.ts` берёт адрес из того, по которому ты открыл сайт, и `callback.ts` отправляет Telegram то же значение. Поэтому открывай `/admin` на том домене, который зарегистрирован |
| GitHub                             | ничего                                                              | Скрипт `npm run sync` читает публичные страницы и публичное API                                                                                                                  |

Пробные сборки (`abc123.имя.pages.dev`) это другие адреса, там вход потребует регистрации каждого. Для админки используй основной домен.

## Шаг 10. Передеплоить

Новые переменные и привязки применяются только к новой сборке. Открой проект Pages, вкладка Deployments, у последней сборки меню (три точки), Retry deployment. Либо сделай любой коммит и `git push`.

## Шаг 11. Первый вход

1. Открой сайт и набери на странице слово `admin` (либо дважды перейди по адресу `/admin`).
2. Нажми Войти через Telegram и подтверди вход в Telegram.
3. Если ID ещё не вписан или записан неверно, откроется страница «Доступ закрыт» с твоим ID. Впиши его в `ADMIN_TG_ID`, передеплой и повтори вход.

## Шаг 12. Проверка

1. В админке на странице Обзор блок «Состояние системы» должен быть зелёным.
2. Открой сайт в обычном окне браузера. Через несколько секунд в Аналитике появится просмотр. Боты и режим Do Not Track не считаются.
3. В Контенте поменяй текст, нажми Сохранить и через минуту обнови сайт.

## Свой домен (по желанию)

Проект Pages, Custom domains, Set up a custom domain. Если домен куплен в другом месте, Cloudflare подскажет, какие DNS-записи добавить. После этого добавь новый домен и новый redirect в Allowed URLs в BotFather.

## Обновление сайта

- Любой `git push` в основную ветку запускает новую сборку.
- Если в папке `migrations/` появились новые файлы, выполни `npm run db:migrate`. Сейчас их семь: `0006` создаёт таблицы блога, комментариев, реакций и блокировок, `0007` добавляет ответы на конкретные комментарии. Для входа посетителей в блог новый адрес в BotFather добавлять не нужно: используются те же адреса, что и для админки.
- Данные в базе (тексты из админки, аналитика) при обновлении сайта не теряются.

## Локальный запуск с админкой

```bash
cp .dev.vars.example .dev.vars     # заполни значения, файл не коммитить
npm run dev:api
```

Сайт откроется на `http://localhost:8788`. Скрипт сам применяет миграции к локальной базе. Вход через Telegram локально может не работать: Telegram принимает только заранее зарегистрированные адреса, а многие настройки не пропускают `http://localhost`. Если так, проверяй вход на развёрнутом `pages.dev`. Остальные разделы админки при этом можно смотреть и без входа, запустив `npm run build:demo` и открыв `dist-demo/admin.html`.

## Резервные копии

- Контент: в админке Контент, кнопка Скачать копию (JSON).
- Вся база: `npx wrangler d1 export snak-db --remote --output backup.sql`.

## Если что-то не работает

| Что видишь                        | Что делать                                                                                                                                                                                                                                                                                                                                                             |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `no such table: ...`              | Не применены миграции. Локально `npm run db:migrate:local`, на проде `npm run db:migrate`                                                                                                                                                                                                                                                                              |
| Telegram пишет `origin required`  | Telegram не узнал запрос как вход по OIDC. Проверь по порядку: 1) в BotFather включён Web Login (OpenID Connect); 2) в Allowed URLs добавлены адрес сайта и точный адрес `/api/auth/callback` для того домена, на котором пробуешь (для `http://localhost` Telegram может не принимать адрес, проверяй на `pages.dev`); 3) `TG_CLIENT_ID` равен Client ID из BotFather |
| Страница «Доступ закрыт» с числом | Это твой ID, которого нет в `ADMIN_TG_ID`. Впиши и передеплой                                                                                                                                                                                                                                                                                                          |
| После входа снова просит войти    | Cookie не сохранилась. Сайт должен открываться по https (или localhost)                                                                                                                                                                                                                                                                                                |
| В аналитике пусто                 | Открой сайт в обычном окне, не в режиме разработчика с блокировщиками. Do Not Track и боты не считаются                                                                                                                                                                                                                                                                |
| Ответ `server_error`              | Смотри логи. Панель, проект Pages, Functions, Real-time Logs. Либо `npx wrangler pages deployment tail`                                                                                                                                                                                                                                                                |
| Не заходит с чужого устройства    | Возможно, адрес заблокирован. В Безопасности есть список блокировок                                                                                                                                                                                                                                                                                                    |

## Лимиты бесплатного плана

На момент написания: 100 000 запросов к функциям в сутки, D1 до 5 ГБ, 5 млн прочитанных и 100 000 записанных строк в сутки. Запросы за статическими файлами не считаются. Счётчик посещений сам останавливается на 4000 просмотров в сутки, чтобы админка продолжала сохранять данные. Клики по ссылкам считаются один раз на посетителя и ссылку в сутки, а на одного посетителя действуют лимиты (20 просмотров и 40 разных ссылок в день), поэтому накрутить цифры нельзя. Актуальные цифры смотри в документации Cloudflare.
